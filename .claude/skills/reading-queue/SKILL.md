## When to invoke
"이제 뭘 읽지"를 물을 때, 또는 ingest 세션을 시작하기 전에 목록을 받고 싶을 때. vault 점검(`wiki-lint`)과는 다른 순간의 질문이므로 별도로 부른다.

부르지 말 것:
- 논문을 실제로 넣는 것 → `paper-ingest`.
- 링크·고아·모순 등 정합성 점검 → `wiki-lint`.

## 핵심 원칙 — 큐를 저장하지 않는다
대기열을 파일에 적고 체크하면 곧 거짓말을 시작한다(ingest했는데 체크 안 함 → 목록과 vault가 어긋남). 대신 **매번 vault에서 유도한다**:

- 논문을 ingest하면 그 논문을 가리키던 깨진 wikilink가 해석되고, 다음 스캔에서 자동으로 빠진다. **완료 체크가 필요 없다.**
- 저장할 것은 사람의 판단 하나뿐 — **"이건 안 읽기로 함"**. `_meta/reading-queue.md`에 이유와 함께 누적한다.
- 그 파일은 상태 저장소일 뿐이고, 사용자 인터페이스는 본 스킬의 출력이다.

## 소스 (3곳)

| # | 소스 | 뜻 | 판정 |
|---|---|---|---|
| S1 | **깨진 wikilink** | 어떤 노트가 `[[X]]`로 가리키는데 X 노트가 없음 | 기계적 — `wiki_backlinks()` 응답의 "깨진 링크" 블록 |
| S2 | **본문이 이름만 부르는 미수록 논문** | hub·통찰 노트 산문에 논문 이름이 평문으로 있는데 vault에 없음 | **LLM 판정 필요** (아래) |
| S3 | **통찰 노트의 열린 질문** | `notes/*.md`의 `## 열린 질문` 항목 | 논문이 특정되지 않으면 검색어로만 제시 |

### S2 판정 규칙 (두 번 거른다)
1. **vault에 이미 있는가** — 본문은 축약 표기로 부르고 slug는 부제까지 붙는 경우가 많다: `HaluMem` → `halumem-memory-hallucination`, `MemOS` → `memos-memory-os`, `Zep` → `zep-temporal-knowledge-graph`. 문자열 매칭으로는 놓치므로 **뜻으로 대조**한다. 있으면 대기열이 아니라 **링크 누락**이므로 `wiki-lint`로 넘긴다.
2. **논문인가 개념인가** — `MoE` · `BM25` · `SFT` · `CNN` · `Reinforcement Learning` 같은 개념어·기법명은 제외한다. 특정 논문을 지칭하는 고유명(`Mem0`, `FinCon`, `Profit Mirage`)만 남긴다. 애매하면 제외 쪽으로 — 대기열은 짧아야 읽힌다.

## 우선순위 — "그것의 부재로 무엇이 막혀 있는가"
평평한 목록은 읽히지 않는다. 아래 순서로만 정렬한다.

| 등급 | 조건 |
|---|---|
| **P1** | hub 서사가 의존 **그리고** 다른 항목이 그것 때문에 막혀 있음 (통찰 판정 보류, 열린 질문의 대상 등) |
| **P2** | hub 본문이 이름을 부르는데 vault에 없음 — 그 hub의 서사가 미수록 논문 위에 서 있다는 뜻 |
| **P3** | 논문 노트가 `[[X]]`로 참조 — 이미 읽은 논문이 필요로 함 |
| **P4** | 다이제스트만 언급 — 소개됐을 뿐 아무도 참조하지 않음 |

같은 등급 안에서는 **참조하는 노트 수**가 많은 순.

## Steps (tool sequence)

| # | 동작 | 도구 |
|---|---|---|
| 1 | 깨진 링크 수집 (S1) — 출처 노트가 `papers/`인지 `digests/`인지 기록 (P3/P4 구분에 쓰임) | `wiki_backlinks()` |
| 2 | hub 목록 + 본문 읽기 (S2) — hub는 15개 안팎·노트당 30줄 수준이라 저렴 | `wiki_list_hubs()` → `wiki_read_note(hub)` |
| 3 | 통찰 노트의 열린 질문 수집 (S3) | `wiki_list("notes")` → `wiki_read_note` |
| 4 | S2 판정 — vault 기수록 여부(뜻으로 대조) → 개념어 제외 | (LLM 추론) |
| 5 | 제외 목록 대조 | `wiki_read_note("_meta/reading-queue")` |
| 6 | P1~P4 등급 부여 + 정렬 → 출력 | (LLM 추론) |
| 7 | (사용자가 제외를 지시할 때만) 제외 목록 append | `wiki_write_note("_meta/reading-queue", ...)` |

Step 4에서 "vault에 이미 있음"으로 판정된 항목은 대기열에서 빼고 **링크 누락 후보로 따로 보고**한다 — `wiki-lint`가 처리할 몫이다.

## 제외 목록 형식 (`_meta/reading-queue.md`)
한 줄 = 한 항목. 되살리려면 줄을 지운다.

```markdown
# Reading Queue — 제외 목록

여기 적힌 항목은 대기열 스캔에서 빠진다. 다시 보고 싶으면 해당 줄을 삭제한다.

- BM25 — 개념·기법명이지 논문이 아님
- Mini-o3 — 관심 밖 (2026-09-02)
```

## Output format (사용자 응답)

```
📚 reading-queue — 후보 {N}건 (제외 {E}건 반영)

P1 — 지금 이걸 못 읽어서 다른 게 막혀 있음
  1. {이름} — {막고 있는 것}. 참조: {노트 slug} 외 {k}곳

P2 — hub 서사가 미수록 논문 위에 서 있음
  2. {이름} — {hub}가 본문에서 부르는데 vault에 없음

P3 — 읽은 논문이 필요로 함
  3. {이름} — [[{참조 논문}]]이 가리킴

P4 — 소개만 됐고 아무도 참조 안 함  ({k}건, 목록 생략 가능)
  {이름}, {이름}, …

🔗 대기열 아님 — vault에 이미 있으나 링크만 누락 ({m}건)
  {본문 표기} → [[{실제 slug}]]   (wiki-lint L8)

❓ 논문 미특정 — 검색어만 ({j}건)
  "{검색어}" — {어느 열린 질문에서}

→ 제외할 항목이 있으면 말씀하세요. 이유와 함께 기록합니다.
```

## Failure handling
- `_meta/reading-queue.md` 없음 → 첫 실행. 제외 0건으로 진행하고, 사용자가 제외를 지시할 때 헤더와 함께 새로 만든다.
- S1·S2 모두 0건 → "대기열 비어 있음". vault가 자기 참조를 다 채운 상태이므로 그대로 보고하고 종료.
- 후보가 `limit`를 넘음 → 상위만 보이고 나머지는 등급별 개수로. **P4는 개수만 보여도 된다.**
- Step 2에서 hub가 없음(초기 vault) → S1·S3만으로 진행.
- 같은 논문이 여러 소스에서 나옴 → 한 항목으로 합치고 가장 높은 등급을 준다. 참조처는 모두 나열.

## 후속 호출 제안
- 목록에서 고른 논문은 `paper-ingest`로. ingest 후 재실행하면 그 항목은 자동으로 빠져 있다.
- "링크만 누락" 항목이 나왔으면 `wiki-lint`(L8).
- 대기열이 P4로만 채워져 있으면 읽을 게 급한 것이 아니라는 신호 — `wiki-lint` L4(hub 본문 갱신)가 더 급할 수 있다.
